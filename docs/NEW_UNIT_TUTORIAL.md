# 신규 유닛 추가 완전 아키텍처 튜토리얼 (New Unit Creation Tutorial)

## 1. 개요 (Overview & 4-Stage Pipeline)

《임진록 2+ 조선의 반격: 여명》 게임 엔진에서 완전히 새로운 커스텀 유닛을 인게임에 등장시키고 정상적으로 생산 및 조종하기 위해서는, 단순히 바이너리 하나만 수정해서는 불가능하며 **에셋, 텍스트 데이터, 스탯 정의, UI 커맨드 카드**의 4대 계층이 유기적으로 연결되어야 합니다.

```
[Step 1: ImgFile.dat]  ──► 신규 유닛 스프라이트(.spr) 경로 및 ID 등록
         │
[Step 2: Text_kor.dat] ──► 인게임 한국어 유닛 이름 및 툴팁/설명문 등록
         │
[Step 3: dawn.exe]     ──► UnitDef::Init 호출을 통한 유닛 스탯/속성 정의 생성
         │
[Step 4: Code Cave]    ──► 0x004e4c6b 미사용 슬랙 공간에 커맨드 카드 버튼 주입
```

본 튜토리얼에서는 가상의 신규 유닛인 **조선 철갑기병(Ironclad Cavalry)** 을 조선 훈련소(Barracks)에서 생산할 수 있도록 등록하는 전 과정을 단계별로 상세히 설명합니다.

## 2. Step 1: 스프라이트 등록 (`ImgFile.dat`)

### 2.1 파일 구조 및 코덱
`ImgFile.dat`는 `Data` 아카이브 내부에 존재하는 탭(`\t`) 구분 텍스트 파일(CP949 인코딩)입니다. 엔진이 사용할 모든 스프라이트(`.spr`)의 심볼릭 ID와 고유 번호를 정의합니다.

- **컬럼 구조**: `파일 ID \t 번호 \t 파일 경로 \t 프리로드 플래그`
- **기존 번호 범위**: 0번(`fnt\mouse.spr`) ~ 337번

### 2.2 신규 스프라이트 등록 절차
1. `tools/archive/` 도구를 사용하여 `Data.hq`와 `Data`를 언패킹합니다:
   ```bash
   python -m tools.archive.cli unpack --input-dir C:\src\reverse-imzinrok\YM\dawn --output-dir ./unpacked_data
   ```
2. `./unpacked_data/ImgFile.dat` 파일의 마지막 행(338번째 줄)에 신규 엔트리를 추가합니다:
   ```text
   FILE_UNIT_HEAVYHORSEK	338	char\heavyhorse.spr	0
   ```
   - `FILE_UNIT_HEAVYHORSEK`: 신규 심볼릭 식별자
   - `338`: 신규 스프라이트 고유 번호 (Sprite ID = 338, `0x0152`)
   - `char\heavyhorse.spr`: 실제 그래픽 파일 경로 (Version 9 .spr 규격)
   - `0`: 온디맨드 로딩 플래그 (게임 시작 시 메모리를 점유하지 않고 생산 시 로드)
3. 해당 `.spr` 파일을 `char/` 디렉터리에 배치한 후 `Data`와 `Data.hq`를 리패킹합니다.

## 3. Step 2: 한국어 텍스트 및 툴팁 등록 (`Text_kor.dat`)

### 3.1 파일 구조 및 포맷 규칙
`Text_kor.dat`는 1,054개 이상의 행으로 구성된 인게임 스트링 테이블입니다.

- **포맷**: `<StringID>, ""<문자열 내용>""`
- **주의사항**: 반드시 큰따옴표 2개(`""`)로 텍스트를 감싸야 엔진의 파서가 정상 인식합니다.
- **스트링 ID 대역**:
  - `1000` ~ `1999`: 조선 유닛/건물 이름
  - `2000` ~ `2999`: 일본/명나라 유닛 이름
  - `3000` ~ `4999`: 연구/업그레이드 및 툴팁 설명문

### 3.2 신규 유닛 텍스트 등록
`./unpacked_data/Text_kor.dat`에 신규 유닛의 명칭과 툴팁을 추가합니다:
```text
1450, ""조선 철갑기병""
3450, ""철갑기병 생산 (쌀: 300, 금: 100)\n중장갑과 마갑을 두른 조선의 최정예 돌격 기병입니다.""
```
- 유닛명 StringID: `1450`
- 툴팁 StringID: `3450`

## 4. Step 3: `dawn.exe` 유닛 스탯 생성자 등록

### 4.1 BSS 배열 및 유닛 ID 할당
엔진은 `0x009b5228` 번지부터 916바이트 스트라이드로 유닛 정의 구조체(`UnitDef`) 배열을 관리합니다.
바닐라 및 여명 모드에서는 ID 2번부터 111번까지 총 110개 유닛이 정의되어 있습니다. 따라서 신규 유닛은 **Unit ID = 112 (`0x70`)** 번을 사용합니다.
$$\text{UnitDef Address} = 0x009b5228 + (112 \times 916) = 0x009ce518$$

### 4.2 생성자 호출 규격 (`0x0049baa0`)
신규 유닛의 스탯을 초기화하기 위해 `UnitDef::Init`에 전달할 54개 DWORD 스택 인자를 구성합니다.

| 인자 순서 | 값 (예시) | 의미 |
|:---:|:---:|:---|
| `arg[0]` ~ `arg[3]` | `0` | 기본 초기화 플래그 |
| `arg[4]` | `0x01` | 유닛 분류 (지상 근접 전투 유닛) |
| `arg[5]` | `650` | **최대 체력 (HP = 650)** |
| `arg[6]` | `0` | 최대 마나 (MP = 0) |
| `arg[11]` | `35` | **생산 시간 (35초 / 35틱)** |
| `arg[12]` | `16` | **공격 딜레이 (16 프레임)** |
| `arg[16]` | `300` | **쌀 비용 (300)** |
| `arg[17]` | `0` | 감자 비용 (0) |
| `arg[18]` | `100` | **금 비용 (100)** |
| `arg[20]` | `6` | **방어력 (6)** |
| `arg[24]` | `8` | **시야 (8)** |
| `arg[25]` | `1` | **사거리 (1 - 근접)** |
| `arg[26]` | `45` | **기본 공격력 (45)** |
| `arg[29]` | `8` | **기본 이동 속도 (8 - 고속 기병)** |
| `arg[30]` | `9` | **돌격 이동 속도 (9)** |
| `arg[34]` | `0x00000004` | 테크트리 요구조건 (마구간 건설 완료 필요) |
| `arg[44]` | `338` | **스프라이트 번호 (`ImgFile.dat` 338번)** |
| `arg[45]` ~ `arg[53]` | `0` | 보조 스프라이트 및 예약 인자 |

## 5. Step 4: 커맨드 카드 버튼 주입 및 코드 케이브 (`0x004e4c6b`)

### 5.1 커맨드 카드 등록 API: `CCommandCard::AddButton` (`0x00412000`)
조선의 반격 엔진의 커맨드 카드는 4×3 그리드(총 12개 슬롯, 0~11번)로 구성됩니다.
버튼 등록 함수의 시그니처:
```c
void __thiscall CCommandCard::AddButton(
    uint16_t slot,     // [esp+0x14] 슬롯 인덱스 (0..11)
    uint16_t cmdId,    // [esp+0x18] 커맨드/유닛 ID
    uint16_t req1,     // [esp+0x1c] 테크 요구 1
    uint16_t req2,     // [esp+0x20] 테크 요구 2
    uint16_t req3,     // [esp+0x24] 테크 요구 3
    uint16_t req4,     // [esp+0x28] 테크 요구 4
    uint16_t req5,     // [esp+0x2c] 테크 요구 5
    uint16_t req6      // [esp+0x30] 테크 요구 6
);
```
- `this` 포인터(`ecx`): 현재 선택된 건물/유닛 인스턴스 포인터(`esi`).

### 5.2 여명 모드 코드 케이브 분석 및 917바이트 잔여 슬랙 공간
여명 모드 제작자는 `.text` 섹션의 끝부분 여유 공간(`0x004e4ae6` ~ `0x004e4c6a`, 총 389바이트)을 활용하여 거북선, 호선, 김덕령 등 7개 신규 버튼을 이미 주입했습니다.

```
+---------------------------------------------------------------------------------+
| .text 섹션 파일 오프셋 0x000e4000 ~ 0x000e5000 (총 4,096 바이트 블록)           |
+---------------------------------------------------------------------------------+
| 0x004e1000 ~ 0x004e4ae5 : 바닐라 엔진 원본 코드                                  |
| 0x004e4ae6 ~ 0x004e4c6a : 여명 모드 기사용 코드 케이브 (389 바이트)            |
| 0x004e4c6b ~ 0x004e4fff : ★ 미사용 순수 슬랙 공간 (917 바이트, 0x00으로 채워짐) |
+---------------------------------------------------------------------------------+
```
**핵심 발견**: `0x004e4c6b`부터 `0x004e4fff`까지 **917바이트의 실행 가능한 완전한 빈 공간**이 존재하므로, 추가 섹션을 확장하거나 PE 헤더를 건드리지 않고도 안전하게 커스텀 어셈블리 루틴을 주입할 수 있습니다.

## 6. 통합 쉘코드 주입 실습 (조선 훈련소에 버튼 추가)

### 6.1 후킹 대상 사이트 선정
조선 훈련소(Barracks, Unit ID 74)의 커맨드 카드 구성 루틴(`0x00480fe0`)에서 기존 마지막 버튼을 등록하는 호출부:
- **후킹 주소**: VA `0x00480ff2` (파일 오프셋 `0x00080ff2`)
- **기존 바이트**: `e8 09 10 f9 ff` (`call 0x00412000`)

### 6.2 슬랙 공간(`0x004e4c70`)에 주입할 어셈블리 쉘코드
```x86asm
[Bits 32]
[Org 0x004e4c70]

; 1. 기존에 가로챈 원래 AddButton 호출 수행
call 0x00412000          ; E8 8B D3 F2 FF

; 2. 신규 유닛(철갑기병) 테크트리 요구조건 6개 푸시 (req6 down to req1)
push 0                   ; 6A 00 (req6)
push 0                   ; 6A 00 (req5)
push 0                   ; 6A 00 (req4)
push 0                   ; 6A 00 (req3)
push 0                   ; 6A 00 (req2)
push 0                   ; 6A 00 (req1)

; 3. 신규 커맨드 ID 푸시 (철갑기병 생산 명령 cmdId = 0x120)
push 0x120               ; 68 20 01 00 00

; 4. 빈 슬롯 인덱스 푸시 (조선 훈련소의 빈 슬롯 9번 슬롯 사용)
push 9                   ; 6A 09

; 5. this 포인터(건물 인스턴스) 복원
mov ecx, esi             ; 8B CE

; 6. CCommandCard::AddButton 호출하여 신규 버튼 등록
call 0x00412000          ; E8 6E D3 F2 FF

; 7. 원래의 후킹 지점 다음 명령어로 복귀
jmp 0x00480ff7           ; E9 77 C3 F9 FF
```

### 6.3 후킹 지점 수정
파일 오프셋 `0x00080ff2`의 5바이트를 슬랙 케이브로 향하는 상대 점프(`jmp 0x004e4c70`)로 덮어씁니다:
$$\text{disp32} = 0x004e4c70 - (0x00480ff2 + 5) = 0x00063c79$$
- **수정 바이트**: `E9 79 3C 06 00`

## 7. 검증 및 테스트 체크리스트

모딩 적용 후 게임을 실행하여 다음 항목을 검증합니다:
1. **바이너리 무결성**: `dawn.exe` 파일 크기가 1,032,192 바이트이며 실행 시 충돌이 없는가?
2. **건물 선택 시 UI**: 게임 내에서 조선 훈련소를 클릭했을 때 9번 슬롯에 철갑기병 아이콘이 정상 표시되는가?
3. **툴팁 및 이름**: 마우스를 올렸을 때 "조선 철갑기병" 텍스트와 3450번 설명문이 팝업되는가?
4. **자원 소모 및 생산**: 버튼 클릭 시 쌀 300, 금 100이 차감되고 35초 후 유닛이 정상 배치되는가?
5. **인게임 조작**: 생성된 철갑기병을 우클릭하여 이동 및 적 공격 시 정상 애니메이션과 사운드가 출력되는가?
