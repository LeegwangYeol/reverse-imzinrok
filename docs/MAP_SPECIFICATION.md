# 임진록 2+ .map 바이너리 포맷 상세 기술 명세서 (Map Specification)

## 1. 개요 및 고정 크기 아키텍처 (Overview & Fixed Size Architecture)

본 문서는 《임진록 2+ 조선의 반격: 여명》에서 사용하는 지도 파일(`.map`)의 바이너리 구조, 메모리 레이아웃, 지형 격자, 자원 배치 및 2D 미니맵 렌더링 수식을 완벽하게 규명한 정밀 기술 명세서입니다.

### 1.1 파일 크기 결정 원리
- **고정 파일 크기**: 정확히 **`1,132,876` 바이트 (`0x11494C`)**
- 모든 `.map` 파일은 실제 전장 크기(가로×세로 70×70, 100×100, 140×140 등)와 무관하게 **항상 동일한 1,132,876 바이트**를 갖습니다.
- 이는 게임 엔진(`dawn.exe`) 및 맵 에디터(`Map Editor.exe`)의 싱글톤 지도 객체(`CMap`, 메모리 주소 `0x00b3dda8`)가 지원하는 최대 맵 해상도인 **180 × 180** 셀에 맞추어 모든 내부 2D 레이어 배열 버퍼를 통째로 디스크에 직렬화(`fread` / `fwrite`)하기 때문입니다.

### 1.2 180-피치(Pitch) 격자 정렬 규칙
- 파일 내부의 모든 2D 지형 및 오브젝트 레이어는 행 스트라이드(Row Stride / Pitch)가 **180**으로 고정되어 있습니다.
- 셀 좌표 $(x, y)$의 레이어 내 상대 오프셋:
  - **8-bit 레이어**:
    $$\text{Offset}(x, y) = y \times 180 + x$$
  - **16-bit 레이어 (uint16)**:
    $$\text{Offset}(x, y) = (y \times 180 + x) \times 2$$
- **유효 영역**: $0 \le x < \text{width}$, $0 \le y < \text{height}$
- **패딩 영역**: $x \ge \text{width}$ 또는 $y \ge \text{height}$인 잉여 셀들은 항상 **`0x00`** 으로 채워져야 엔진의 메모리 오버런 방지 검사를 통과합니다.

## 2. 헤더 메타데이터 오프셋 맵 (`0x000000` ~ `0x003ae3`)

| 오프셋 (Hex) | 크기 (Bytes) | 자료형 | 필드명 | 의미 및 유효 범위 |
|:---|:---:|:---:|:---|:---|
| `0x000000` | 4 | `uint32` | `version` | 맵 포맷 버전 (항상 `0x00000001`) |
| `0x000004` ~ `0x000087` | 132 | `uint8[132]` | `reserved_header` | 헤더 예약/패딩 (`0x00`) |
| `0x000088` | 4 | `uint32` | `player_count` | **최대 참가 플레이어 수** (`2`, `3`, `4`, `5`, `6`, `8`) |
| `0x00008c` | 2 | `uint16` | `width` | **전장 가로 타일 너비** (`70` ~ `180`) |
| `0x00008e` | 2 | `uint16` | `height` | **전장 세로 타일 높이** (`70` ~ `180`) |
| `0x000090` | 4 | `uint32` | `theme_id` | **타일셋 테마 ID** (`0` ~ `6`, 테마 매핑 참조) |
| `0x000094` ~ `0x0000af` | 28 | `uint8[28]` | `map_flags` | 맵 속성 플래그 및 기후 조건 |
| `0x0000b0` | 4 | `uint32` | `mode_flag` | 맵 실행 모드 (기본 `0x00000003`) |
| `0x0000b4` ~ `0x0000f3` | 64 | `PlayerStart[8]` | `player_starts` | **8개 플레이어 슬롯별 시작 좌표** (각 8바이트) |
| `0x0000f4` ~ `0x000123` | 48 | `uint8[8][6]` | `player_settings`| 슬롯별 팀, 색상, 활성화 플래그 |
| `0x000124` ~ `0x000143` | 32 | `uint8[32]` | `reserved_players`| 플레이어 예약 영역 |
| `0x000164` ~ `0x001a63` | 6,400 | `uint16[4][800]` | `lookup_tables` | 4종 지형 전이 룩업 테이블 (800워드 × 4) |
| `0x0026e4` ~ `0x003363` | 3,200 | `uint16[8][200]`| `tech_restrictions`| 플레이어별 유닛/생산 허용 비트마스크 |
| `0x003364` ~ `0x0034f3` | 400 | `uint32[100]` | `physics_table_a` | 지형 물리 연산 테이블 A |
| `0x0034f4` ~ `0x003683` | 400 | `uint32[100]` | `physics_table_b` | 지형 물리 연산 테이블 B |
| `0x003684` ~ `0x0036c3` | 64 | `uint32[8][2]` | `handicap_table` | 플레이어 자원/핸디캡 계수 |
| `0x0036c4` ~ `0x003ae3` | 1,056 | `uint8[1056]` | `pre_grid_padding` | 그리드 직전 패딩 영역 |

### 2.1 플레이어 시작 좌표 구조체 (`0x0000b4` ~ `0x0000f3`)
8개의 플레이어 슬롯마다 8바이트씩 할당됩니다:
```c
struct PlayerStartPos {
    uint32_t start_x;  // 시작 타일 X 좌표 (0 ~ width - 1)
    uint32_t start_y;  // 시작 타일 Y 좌표 (0 ~ height - 1)
};
```
- **미사용 슬롯**: 해당 슬롯에 플레이어가 배정되지 않은 경우 `start_x = 0xFFFFFFFF`, `start_y = 0xFFFFFFFF` (`-1, -1`)로 기록됩니다.

### 2.2 테마 ID 매핑 (`0x000090`)
`Map Editor.exe`의 `0x00418ccc` 테마 테이블에 정의된 7종 타일셋 디렉터리입니다:

| 테마 ID | 타일 디렉터리 | 지형 시각 특성 | 대표 맵 예시 |
|:---:|:---|:---|:---|
| `0` | `tile\normal\` | 일반 온대 평원 및 초원 | 대부분의 표준 대전 맵 |
| `1` | `tile\snow\` | 설원, 빙판, 눈 덮인 산 | `눈속에묻힌싸움터.map` |
| `2` | `tile\brown\` | 건조한 황무지 및 황토 | `메마른 땅.map` |
| `3` | `tile\green\` | 울창한 밀림 및 습지 | `삶과죽음의갈림길.map` |
| `4` | `tile\dark\` | 어두운 암석 지대, 야간 전장 | `태풍의눈.map` |
| `5` | `tile\volcano\` | 용암 대지 및 검은 화산암 | `화산도.map` |
| `6` | `tile\bright\` | 백사장, 밝은 사막, 해변 | `남해의 작은 섬.map` |

## 4. 4대 핵심 자원 및 중립 오브젝트 시스템

게임 내 일꾼 유닛이 채집하거나 상호작용할 수 있는 자원은 `Resource Grid 3`(`0x0cd63c`)에 기록됩니다:

| 자원 ID | 명칭 | 기본 매장량 (`0x0dd35c`) | 재생 상태값 (`0x0e51ec`) | 게임 내 자원 성격 |
|:---:|:---|:---:|:---:|:---|
| **`1`** | **감자밭 (Potato)** | **`70`** | `5` | 주요 식량 자원. 농부가 채집하여 본영/창고에 납품. |
| **`2`** | **대나무 (Bamboo)** | **`25`** | `5` | 소량 급속 목재 자원. 벌목 속도가 빠름. |
| **`3`** | **나무 / 숲 (Wood)** | **`170`** | `5` | 대규모 목재 자원. 조선/명/일본 공통 핵심 건축 자재. |
| **`100`** | **벼 / 논 (Rice)** | **`40`** | `5` | 고급 식량 자원. 논 형태로 배치되며 수확량 높음. |
| `6` ~ `11` | 고정 지형 중립 암석 | `1` | `5` | 파괴 불가 맵 자연 지물 |
| `30`, `50`, `61`| 중립 건물 / 성문 | `1` | `5` | 점령 가능 건물 또는 시나리오 오브젝트 |

## 5. 2D 미니맵 렌더링 파이프라인 및 공식 (Minimap Rendering Pipeline)

미니맵 렌더러는 맵 파일 내부의 다중 격자 레이어를 읽어 인게임 레이더 미니맵과 동일한 색조의 PNG 이미지를 생성합니다.

### 5.1 해상도 및 캔버스 스케일링
- 원본 맵 해상도: $\text{width} \times \text{height}$ 타일.
- 미니맵 출력 이미지 크기: 시각적 가독성을 위해 기본 4배 확대($4W \times 4H$, Nearest-Neighbor 필터링)하여 렌더링합니다.

### 5.2 픽셀 컬러 결정 우선순위 알고리즘
각 타일 $(x, y)$에 대해 다음 순서로 색상을 결정합니다:

```python
def get_tile_color(x, y, map_data):
    # 1. 지형 기반 색상 (ByteGrid 0 & ByteGrid 1)
    bg0 = map_data.byte_grid_0[y][x]
    bg1 = map_data.byte_grid_1[y][x]
    theme = map_data.theme_id
    
    if bg0 == 1:
        # 수면 / 바다
        return (45, 90, 160)  # Deep Ocean Blue
    elif bg0 == 2:
        if bg1 != 0:
            # 절벽 / 통행 불가 암석
            if theme == 1: return (150, 160, 175) # Snow Cliff
            elif theme == 5: return (60, 30, 30)   # Volcano Rock
            return (110, 95, 75)                   # Cliff Stone
        else:
            # 평지 / 이동 가능 육지
            if theme == 1: return (220, 230, 240) # Snow White
            elif theme == 2: return (170, 130, 90) # Brown Dirt
            elif theme == 5: return (120, 50, 40)  # Volcano Ground
            elif theme == 6: return (210, 190, 140)# Bright Sand
            return (145, 130, 95)                  # Normal Meadow

    # 2. 자원 오버레이 (Resource Grid 3)
    res_type = map_data.resource_grid_3[y][x]
    if res_type == 3:   return (25, 100, 30)   # 나무 (Dark Forest Green)
    elif res_type == 2: return (50, 140, 45)   # 대나무 (Bamboo Green)
    elif res_type == 1: return (200, 160, 40)  # 감자밭 (Crop Yellow)
    elif res_type == 100: return (220, 190, 60)# 벼 / 논 (Golden Grain)

    # 3. 사전 배치 건물 (Preplaced Buildings)
    bldg = map_data.preplaced_0[y][x]
    if bldg != 0:
        owner = map_data.preplaced_1[y][x]
        return PLAYER_COLORS.get(owner, (180, 180, 180))

    return (0, 0, 0)
```

### 5.3 플레이어 시작 지점 마커 렌더링
`0x0000b4` 배열에서 유효한 시작 좌표 $(sx, sy)$를 가져와 해당 위치를 중심으로 $3 \times 3$ 픽셀 십자형 마커를 강조하여 그립니다:
- **P0**: 파란색 `(0, 100, 255)`
- **P1**: 빨간색 `(255, 30, 30)`
- **P2**: 노란색 `(255, 255, 0)`
- **P3**: 초록색 `(0, 220, 0)`
- **P4**: 보라색 `(200, 50, 255)`
- **P5**: 주황색 `(255, 140, 0)`
- **P6**: 하늘색 `(0, 255, 255)`
- **P7**: 분홍색 `(255, 100, 180)`

## 6. 맵 수정 및 프로그래밍 도구 (`tools/map/`) CLI 사용법

### 6.1 맵 메타데이터 분석 및 JSON 덤프
```bash
python -m tools.map.cli parse --map-file "YM/dawn/cusmap/(2인,100X100)삶과죽음의갈림길.map" --json-out map_info.json
```

### 6.2 2D 미니맵 PNG 이미지 렌더링
```bash
python -m tools.map.cli render --map-file "YM/dawn/cusmap/(2인,100X100)삶과죽음의갈림길.map" --output-png minimap.png
```

### 6.3 자원 및 지형 프로그래밍 수정 후 저장
수정된 맵 파일은 반드시 원본과 동일하게 정확히 **1,132,876 바이트**로 저장되어야 게임 엔진에서 오류 없이 로드됩니다:
```bash
python -m tools.map.cli modify \
    --input-map "YM/dawn/cusmap/(2인,100X100)삶과죽음의갈림길.map" \
    --output-map "./modified.map" \
    --add-resource "x=50,y=50,type=wood,amount=200" \
    --set-player-start "player=0,x=25,y=25"
```
