## 2. Righteous Army (`조선 의병`, `0x6E`) Building Entry & Command Card

### A. Building Entry Check (Why `0x70..0x79` Can Enter Allied Joseon Buildings)
- There is **no** hardcoded `KindID == 0x6E` check for entering Joseon buildings or AI building-garrison behavior. Instead, it is controlled entirely by **`Atb2 & 0x20`** (`KindInfo + 0x50` / `cltChar + 0x1DC`):
  1. **`cltChar::CanEnterCarrierOrBuilding` (`0x00413590..0x00413627`)**:
     ```asm
     0x004135F7: test  byte ptr [esi + 0x1dc], 4     ; targetBuilding->Atb2 & 0x04 (Joseon building)
     0x004135FE: je    0x413625
     0x00413600: mov   ecx, edi
     0x00413602: call  0x412120
     0x00413607: cmp   eax, 5                        ; max 5 units inside building
     0x0041360A: jge   0x413625
     0x0041360C: mov   eax, 1
     0x00413611: test  byte ptr [edi + 0x1dc], 0x20  ; unit->Atb2 & 0x20 (ATB2_ENTER_BUILDING)
     0x00413618: jne   0x413622                      ; returns 1 (allowed to enter!)
     ```
  2. **`cltChar::AI_EnterJoseonBuilding` (`0x00414780..0x00414850`)**:
     ```asm
     0x0041478A: test  byte ptr [edi + 0x1dc], 0x20  ; unit->Atb2 & 0x20
     0x00414791: je    0x41484a
     ```
     When `Atb2 & 0x20` is set, AI units automatically scan for friendly Joseon buildings (`Atb2 & 0x04`) and issue Order `0x22` (`34`, Enter Building) via `0x004B0820`.
- Why `0x70..0x79` inherited this: `KindInfo[0x6E]` (`조선 의병`) is initialized at `0x00426D65` with `Atb2 = 0x28` (`0x08 | 0x20`). Because `build_init_cave` copies `KindInfo[0x6E]`, all custom units `0x70..0x79` inherit `KindInfo + 0x50 = 0x00000028`.

### B. Command Card Setup (Why `0x70 유생` Has `조선 의병` Skills `매복`/`지뢰제거`)
- In `0x0047F8F0` (`cltCommand::SetupCommandCard`), the switch jump table at `0x004801C8` (indexed via `KindID - 2`) handles `0x6E` (`조선 의병`) at **`0x00486B50` (`VA_JUSTICEK_CMDCARD`)**:
  - `0x00486BF9`: checks Tech `[edx*4 + 0x95993E] == 1` (`매복`) $\rightarrow$ adds Button `0x2C` (`44`, `매복`) at Slot 8 (`0x00486C14`).
  - `0x00486C24`: checks Tech `[edx*4 + 0x959936] == 1` (`지뢰제거`) $\rightarrow$ adds Button `0x2D` (`45`, `지뢰제거`) at Slot 4 (`0x00486C3F`).
- In `patch_joseon_new_unit.py`, `build_cmdcard_dispatcher` (`0x004E4FD4`) explicitly routes `0x70` to `0x00486B50`:
  ```python
  # Line 141 of tools/modding/patch_joseon_new_unit.py:
  # cmp byte ptr [ecx+0x8D], 0x70 -> je VA_JUSTICEK_CMDCARD (0x00486B50)
  ```
  Meanwhile `0x71..0x79` jump to `VA_SWORDK_CMDCARD` (`0x00486EE0`, generic combat unit command card: Move, Stop, Attack, Hold, Patrol).

### C. Exact Fix to Decouple `0x70..0x79` from `조선 의병` (`0x6E`)
1. **Disable Building Entry & AI Garrisoning**: Clear bit `0x20` in `KindInfo + 0x50` (`Atb2`) inside `build_init_cave`:
   - `and byte ptr [ebx + 0x50], 0xDF` (changes `Atb2` from `0x28` to `0x08`, matching standard infantry like `조선 창병` `0x04`).
   - Also subtract `0x20` from `dword ptr [ebx + 0x08]` (or call `0x0049BD50`) so `KindInfo` checksum stays valid.
2. **Give `0x70 유생` a Standard Combat Command Card**: In `build_cmdcard_dispatcher` (`patch_joseon_new_unit.py`), route `0x70` to `VA_SWORDK_CMDCARD` (`0x00486EE0`) instead of `VA_JUSTICEK_CMDCARD` (`0x00486B50`).

## 3. Bind (`포박술`) and Immobilize/Freeze Status Effects

### A. Why Setting `AttackAtb=9, BulletID=13` (`유성룡`) or `AttackAtb=26, BulletID=12` (`션웨이징`) Did Not Bind/Freeze
- **`0x4E 유성룡`**:
  - `AttackAtb1 = 9`, `BulletID = 13` (`0x0D`).
  - Its active skill is **`현혹` (Betray/Charm, Button `0x17`)**, validated at `0x00477500` and executed at `0x004777E0` (requires Tech `0x9598CC`, costs 60 MP, converts an enemy unit's allegiance).
  - Neither `AttackAtb = 9` nor `BulletID = 13` has any immobilize/bind logic in `cltBullet::Hit1` (`0x00401BB0`) or `CalcAttack` (`0x00470A00`).
- **`0x59 션웨이징`**:
  - `AttackAtb1 = 26` (`0x1A`), `BulletID = 12` (`0x0C`).
  - Its active skills are **`흡수` (Absorb HP, Button `0x35`, `0x00470D60` / `0x00470F50`)** and **`기술훔치기` (Steal Tech, Button `0x3A`, `0x0047EA00` / `0x0047EBF0`)**.
  - In `CalcAttack` (`0x00470A00`), `AttackAtb = 26` (`0x1A`) is simply a normal damage type index into the armor multiplier table `0x004F67E0`.
- **What about Freeze (`빙결/냉동`)?**
  - There is **no** separate "Freeze (`빙결`)" unit status timer in `dawn.exe` (`0x00410210` is `김시민`'s `연옥술` rock-drop spell, `cltChar + 0x378` is `기합` buff overlay `0xF9`, and `cltChar + 0x0C` is poison DoT).
  - The immobilize/bind status effect in `dawn.exe` is **`포박술` (Bind)**, which belongs to **`0x57 명 쑹잉창`**!

### D. Two Ways to Give a Custom Unit (`0x76 도사` or `0x73 구미호`) Bind-on-Attack

## 4. Clone Skill (`분신술` / `[분신 소환]`) for `0x73 구미호`

### A. Disambiguating the Three Clone Mechanisms in `dawn.exe`
1. **`[분신 소환]` (`0x004F4DA4`, referenced at `0x004A97F8`)**:
   - Only a hero item tooltip string (`test dword ptr [eax + 0x669CA8], 0x800` at `0x004A97EB`). Not an active unit skill.
2. **Targeted Illusion (`환영술`, `0x5D 아사코` at `0x00410DE0` / `0x00410FC0` Case 2, and `Atb3 & 0x01` in `0x00477D70`)**:
   - Requires clicking a target unit (`Order 0x34`), costs 40–50 MP, spawns 1 clone of the target.
3. **Self-Clone (`분신술 [C]`, Button `0x39` / 57, Order `0x33` / 51 — used by `0x50 곽재우`)**:
   - Instant self-cast active skill that spawns multiple clones of the caster in a 5x5 grid around the caster using **`Effect\on_effect_foxclon_appear.Spr`** (Smoke ID **`0x3B` = 59**, `FILE_ON_EFFECT_FOXCLON_APPEAR`)!

### B. Complete `분신술` (`0x50 곽재우`) Call Chain & Addresses

3. **`CanClone` (`0x00477CA0..0x00477D63`)**:

4. **`DoClone` (`0x00477D70..0x0047829F`) — The Hardcoded `0x61` (`곽재우분신`) Bottleneck**:
   - At `0x00477E5C`: checks `test byte ptr [ebx + 0x1DD], 8` (`Atb2 & 0x00000800`).

   - At `0x00477EAA`: computes `esi = Player.UnitCountByKind[caster->KindID] + 2` (so if the player has 1 caster, `1 + 2 = 3` clones; if 0, `2` clones).

   - Loops over a 5x5 tile offset grid (`x_off = -2..+2`, `y_off = -2..+2`) around `(caster->TileX, caster->TileY)`:
     - Checks `CanPlaceUnit(KindID, tileX, tileY)` (`0x004A3AC0` at `0x00477FA1`).
     - Calls **`SetChar` (`0x004AC530`)** at **`0x00477FE9`** using `[esp + 0x1C]` as `KindID`, `caster->HP` (`[ebx + 0xB4]`), and `MP = 0`.
     - Deducts **`0x23` (35 MP)** per spawned clone from `caster->MP` (`add eax, -0x23` at `0x00477FFF`).
     - Spawns Smoke ID **`0x3B` (59 = `Effect\on_effect_foxclon_appear.Spr`)** at the clone's pixel position (`push 0x3b; call 0x4ac3e0` at `0x00478033`).
     - Marks the spawned unit as a clone and links it to the caster (`0x00478136..0x00478253`):
       ```asm
       0x00478136: mov   byte ptr [esi + 0x66b804], 1     ; cloneChar->IsClone (+0x74) = 1
       0x0047824D: mov   ecx, dword ptr [ebx + 0x29c]     ; caster->UniqueID (+0x29C)
       0x00478253: mov   dword ptr [esi + 0x66bcaa], ecx  ; cloneChar->CloneOwnerUniqueID (+0x51A) = caster->UniqueID
       ```
5. **Clone Lifespan & Owner-Death Synchronization**:
   - **Gradual HP Decay (`0x0048DD73..0x0048DD96`)**: Whenever `cltChar + 0x51A` (`CloneOwnerUniqueID`) `!= 0`, the clone loses `3` HP per periodic tick (`add eax, -3; mov [esi + 0xB4], eax`) until its HP reaches 0 and it dies.
   - **Instant Death if Caster Dies (`0x0048E14F..0x0048E1A2`)**: Calls `IsAlive(CloneOwnerUniqueID)` (`0x00416F40`); if the caster is dead (`eax == 0`), sets `cloneChar->HP` (`[esi + 0xB4]`) `= 0`.
   - **Visual Clone Tint for Owner (`0x00478942..0x00478977`)**: When `cltChar + 0x74` (`IsClone`) `== 1`, allies draw the clone via `0x0041AC50` (tinted/translucent) while enemies draw it normally.

### C. How to Enable `분신술` for `0x73 구미호` (Spawning `0x73` Clones)
To let `0x73 구미호` use `분신술` and spawn clones of herself (`0x73`):
1. **`KindInfo` Attributes for `0x73 구미호` (in `build_init_cave`)**:
   - Set bit **`0x00000800`** in `KindInfo[0x73] + 0x50` (`Atb2`), e.g. `or dword ptr [ebx + 0x50], 0x00000800` (which sets `byte ptr [ebx + 0x51] |= 0x08`).
   - Give `0x73 구미호` sufficient MP (`KindInfo + 0x80` (`MaxMP`), e.g. `150` or `200`, since spawning 3 clones costs `3 * 35 = 105` MP).
2. **Command Card for `0x73 구미호` (in `build_cmdcard_dispatcher`)**:
   - For `KindID == 0x73`, after building the standard combat buttons (`0x00486EE0`), call `0x004891C0` to add **Button `0x39` (`57`, `분신술[C]`)** at Slot 4 (or route `0x73` to `0x00487790` / a custom block that adds Button `0x39` unconditionally without requiring `곽재우`'s tech `0x9598DC`).
3. **Bypass Tech `0x9598DC` Check for `0x73` (or auto-enable Tech `0x9598DC`)**:
   - `CanClone` (`0x00477CC0`) and button click handler (`0x00475BCA`) check `word ptr [player*0x13EC + 0x9598DC] != 0` (`분신술` tech) and `0x959AF0 != 0`.
   - Either patch `0x00477CC8` (`je 0x477d0b` $\rightarrow$ `NOP`s) and `0x00475BD2` (`je 0x4758bb` $\rightarrow$ `NOP`s) so any unit with `Atb2 & 0x800` and Button `0x39` can cast `분신술` without researching `곽재우`'s tech, OR check `cmp byte ptr [ecx + 0x8D], 0x73`.
4. **Replace Hardcoded `0x61` at `0x00477EC4` so `0x73` Spawns `0x73` (or `caster->KindID`)**:
   - At `0x00477EC4` (`C7 44 24 1C 61 00 00 00`, 8 bytes: `mov dword ptr [esp + 0x1c], 0x61`), `ebx` is the `cltChar*` of the caster (`[ebx + 0x8D]` = `caster->KindID`).
   - If `0x50` (`곽재우`) should still spawn `0x61` (`곽재우분신`) while any other unit (such as `0x73 구미호`) spawns its own `KindID`, a tiny hook at `0x00477EC4` (8 bytes, enough for `call <code_cave>; nop; nop; nop`) can do:
     ```asm
     movzx eax, byte ptr [ebx + 0x8d]   ; eax = caster->KindID
     cmp   al, 0x50                     ; is caster 곽재우 (0x50)?
     jne   .use_self_kind
     mov   al, 0x61                     ; 곽재우 spawns 0x61 (곽재우분신)
     .use_self_kind:
     mov   dword ptr [esp + 0x20], eax  ; (+0x20 inside call, or +0x1c if jmp)
     ret
     ```
   - Or, if you want to avoid a hook at `0x00477EC4` entirely, you don't even need a code cave if `0x50` is not used: replacing the 8 bytes at `0x00477EC4` in-place with:
     ```asm
     0F B6 83 8D 00 00 00   ; movzx eax, byte ptr [ebx + 0x8d]  (7 bytes)
     89 44 24 1C            ; mov dword ptr [esp + 0x1c], eax   (4 bytes)
     ```
     (via a 5-byte `call` into the existing code cave) makes `분신술` dynamically clone the caster's own `KindID` (`0x73 구미호` $\rightarrow$ spawns `0x73 구미호` clones with the fox-clone smoke effect `0x3B`!).
